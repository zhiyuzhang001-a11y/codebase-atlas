## 稳定源码发现与干预范围

以下均来自冻结的 0.27.0 源码，不是当前 Rust checkout 的新增能力。

1. `mcp.py:TOOLS` 已提供 `locate_files`：最多两个候选，明确启发式、非穷尽、须阅读后再找精确符号。没有必要增加自然语言直达函数接口。
2. `change_analysis.py:analyze_change` 及 MCP 路由支持 `response_mode="compact"`，但省略参数仍为 `full`。第一阶段应让指引显式传 compact，不更改 API 兼容默认值。
3. `_compact_brief` 保留目标、推荐阅读、推荐测试、完整性、预算、索引、代际和警告；`_compact_result` 保留边身份、来源与 evidence hash。压缩不能删掉这些决策证据。
4. `codex_integration.py:PROJECT_RULE` 要求任务开始检查状态，并在改代码前做精确分析；版本化技能同时规定已定位局部编辑跳过 Atlas。两者存在指导范围不一致，应收窄为跨文件行为和测试发现等按需场景，而非强制所有改动查询。
5. `reloadable_mcp.py:ReloadableMcpServer` 的 bootstrap initialize instructions 指出根目录和先查状态，但没有完整的候选阅读、精确分析及退路顺序。工具级说明与技能应互相补充，而不是复制庞大流程。
6. `mcp.py:_brief_tool_result` 只将整体 `error` 映射为 `isError`；`partial`、`needs_disambiguation` 可能不触发工具错误标记。消费者必须读取业务状态与 completeness，不能只看 `isError=false` 就宣布成功。这是已有合同语义，不是本轮运行失败。

第一阶段建议只修改版本化技能、项目规则和 MCP instructions/description，并增加相应契约回归。不修改 Provider、排序、图算法、生命周期和 JSON 默认行为，不删除 structuredContent 或 text content。两种 MCP 输出是否会被实际宿主重复载入尚未测量，不因猜测重复就改变协议。

已有相关测试包括 `tests/test_mcp.py` 的候选上限、拒绝 stale、生命周期停用、状态超时、异常后存活、generation、刷新失败和 compact 路由；`tests/test_change_analysis.py` 的紧凑证据一致性、歧义停止、空截断结果为 partial、子查询错误；`tests/test_codex_integration.py` 的只读计划、项目范围、保留外来字节和拒绝覆盖。这里只确认测试源码存在，未执行，不写 PASS。

## 六类使用合同

本节作为实现前设计约束；实际场景回归必须另行运行。

| 场景 | 预期行为 | 禁止行为 |
| --- | --- | --- |
| 已知文件和局部实现 | 直接阅读与普通验证，不为此主动查询 Atlas | 把每次小编辑变成图查询；为读取反复请求权限 |
| 位置未知 | Atlas 已加载且需要其事实时先核对状态；一次 locate，最多读两个候选，再普通源码解析精确身份 | 直接把候选当根因；为换同义词重复定位 |
| 精确跨文件目标 | `symbol` 与 `target_path` 必传，必要时 owner；显式 compact；读源码后决定修改及测试 | 根据关系结果自动修改所有关联文件 |
| 零结果和歧义或 partial | 零结果不等于无实现；同名用源码收窄；缺失关系直接有界补读 | 猜目标、隐去 not_run/truncated、声称不存在测试 |
| unavailable 或 stopped 或 busy | 无工具或 stopped 直接普通阅读；身份错配拒绝其事实；临时 busy 有限等待后回退 | 自动 enable、创建新任务恢复、跨项目借用事实 |
| stale 和源文件变更 | 丢弃不再有效的位置/结论；仅允许已有授权的刷新策略，失败保留状态并回退 | 自动首次索引或换项目配置；沿用旧代结论 |

调用设计限额：每个任务最多一次自然语言定位，两个候选均不相关即普通搜索；明确身份后最多一次初始 Change Brief。允许一次针对已报告重要证据缺口的有界精确查询，但不重复同一批结果。busy/startup 最多一次重试，共享最多 60 秒 Atlas 等待额度，额度耗尽即回退。每次调用 timeout 不得超过剩余等待额度，不能在工具启动等待后重新计时。以上是候选行为预算，不是已实现的运行监督器；历史冷启动时间不能保证这个额度内成功。

相同证据的复用必须核对 repository、源码状态、generation 和 freshness。读取区域按相对路径、文件内容摘要及行区间去重；摘要变化后视为新的源码版本。相同版本重叠行数记重复阅读，不把它等同模型 token。当前无条件收集源码全文的授权，验收记录只采集必要的位置、摘要和判断依据。

## 真实宿主隔离与恢复设计

官方文档说明项目 `.codex/config.toml` 可配置 MCP，但仅对可信项目生效，并提供 server enabled、工具允许/拒绝列表；这使项目范围隔离在配置层具有候选路径，不证明当前桌面任务已加载隔离配置。MCP server instructions 的前 512 字符应包含最重要且自足的跨工具指引。[OpenAI MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)

后续宿主开发验证需要两个隔离的私有项目身份，而不是改当前父/子项目：普通组不加载 Atlas MCP 和 Atlas 专属技能/规则；候选组加载准确候选及其对应指引。双方共同非 Atlas 规则、模型、推理设置、权限和源码快照一致。还须检查继承的父目录 AGENTS、全局规则、插件和可发现工具，不能仅删除一个项目表就认定对照无 Atlas 指导。

实际加载验证必须在新会话完成：记录工具发现、initialize 根目录、候选来源、实际配置差异以及 trace 时间戳；对照组验证无 Atlas 工具和专属路由，候选组验证准确根目录、正查询及错项目负控制。当前没有执行该验证，私有候选接入路线仍为待验证。

恢复前记录授权临时配置的原始字节、文件摘要和存在状态。恢复只涉及该私有连接、其临时配置、明确所属进程及候选源码/技能；不能停止其他项目 MCP、替换共享 Provider 或修改全局配置。存在外来修改时停止自动恢复，保留双方证据。首次索引、候选打包或私有接入若需要执行项目代码，执行范围必须单列，不由只读阶段零批准推定。

## 数据与主指标合同

三组数据不复用：开发回归集使用可见合成场景和既有回归；真实宿主开发集仅用于接入与行为校准；独立集由独立评分者封存，最终候选冻结后正式运行一次。当前未选择新独立仓库或任务、未封存真值，不能称数据分离完成。

独立集设计为 12 个配对任务：Python 与 TS/JS 各 6 个，每语言 1 个已知局部任务、2 个未知位置任务、2 个跨文件任务、1 个失败回退任务；另设身份错配、停用、partial、stale 安全控制。效率主指标适用子集固定为 8 个未知位置及跨文件任务，不根据结果改变适用集。独立评分者必须在运行前验证任务真值、隐藏测试和证据区域；不得将答案或另一组轨迹发给工作会话。

唯一效率主指标是首个有效源码证据时间：从宿主记录公共任务送达事件，到首次完成读取独立真值对应实现区域且满足预先任务判定条件的事件。Atlas 输出候选、搜到文件名或最后答案正确都不算完成该事件。只有位置与事件时间可复核才可计量；没有真实宿主 trace 就不得用 shell 计时或最终回答反推。

对每个适用任务，普通组时间为 B，候选组为 C，配对改善为 `(B-C)/B`。B=0 且 C=0 记 0；B=0 且 C>0 记 -1，并单列数量。未取得有效证据或超时记预注册会话上限 15 分钟；未完成会话不得从分母删除。主指标配对改善中位数须 >=20%。所有 12 个任务的端到端完成耗时逐会话记录，失败/超时同样记上限；候选中位数不得超过普通组中位数的 1.10 倍。该 15 分钟限额在成本校准前是设计参数；如果校准导致修订，须在正式封存前更新合同版本，不能运行后改门。

正确性逐任务独立评分并报告双方通过、仅普通组通过、仅候选通过、双方失败四类。仅普通组通过而候选失败必须为零，安全控制全部通过；未观测测试不能计通过。无有效证据、全失败或主指标不可采集均不宣布收益。评分使用去方案标识轨迹；若工具名使评分者可推知方案，记录残余非盲性，不能宣称完全盲评。
