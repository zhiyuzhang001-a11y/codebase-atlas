# Atlas 四命令生命周期计划

状态：第一阶段已完成；第二阶段进行中（生命周期状态与项目操作锁已完成）。

## 目标与范围

对普通用户只提供 `atlas enable`、`atlas stop`、`atlas update`、`atlas remove` 四个日常操作。默认目标为当前工作目录所属的准确 Git 仓库；无法确定目标时明确报错，可通过 `--repo` 指定。PDF 项目的部署不属于本计划本轮范围。

复用现有 onboarding、索引、项目发现、Provider 生命周期和 MCP 能力，避免维护第二套实现。保留 `codebase-atlas` 和现有高级命令的兼容性，增加 `atlas` 入口；安装时发现同名外部程序不得覆盖。

## 命令契约

### enable

- 检查稳定 Release、校验记录和运行时，优先复用已经验证的机器安装。
- 首次缺少 Atlas 管理的运行时时，在版本化用户目录内按发布清单准备；不修改系统包管理器、全局 Python 或编辑器设置。
- 缺少不能自动准备的必要依赖时，明确报告失败步骤，不宣布可用。
- 验证当前仓库身份，创建或恢复项目配置，构建或刷新专属索引，准备项目连接。
- 重复执行为幂等操作；停止后执行恢复项目。存在不同配置时不覆盖。
- 配置就绪、索引就绪与宿主连接状态分别报告；完整成功需要真实目标查询验证。

### stop

- 将项目标记为停止，停止接收新查询和自动刷新；下一次查询不能自动重新启用。
- 对进行中的刷新采用有界等待或现有安全取消机制，保持事务一致性。
- 释放本项目后端和连接资源，保留配置、索引和恢复所需状态。
- 不终止其他项目正在使用的共享 Provider。停止状态下重复执行仍成功。

### update

- 显式升级到最新非草稿、非预发布的稳定 Release，校验后安装到新的版本目录。
- 验证兼容性，执行必要迁移、健康检查和目标查询，然后原子切换当前项目所用版本。
- 更新失败保留旧版本与旧数据；迁移不可原地回退时必须使用隔离副本或备份，不允许先破坏旧数据。
- 其他项目继续使用自己的版本选择；共享新版本不等于强制升级所有项目。
- 已停止项目更新后仍保持停止。未启用项目提示先 enable，不隐式启用。
- 源码改动由查询前自动刷新处理，用户无需为日常代码改动运行 update。

### remove

- 先停止当前项目，移除仅由 Atlas 管理且身份匹配的项目接入和配置。
- 将项目专属数据移动到 Atlas 管理的恢复区，并返回恢复位置和收据；首版不自动永久清除。
- 保留业务源码、无关配置、其他项目数据和共享安装。外部或无法证明所有权的数据拒绝删除。
- 重复执行为幂等操作。旧连接收到明确的已移除状态，不能自动重新建库。

## 内部设计

### 项目状态与串行化

项目使用唯一身份和独立操作锁。状态至少包含未启用、启用中、可用、停止中、已停止、更新中、已移除，以及失败原因和最后一次可用版本。状态文件不能替代真实健康检查。

每次操作记录意图、已完成阶段和回退信息，原子发布最终状态。崩溃后可以重试或恢复。项目锁与已有刷新锁必须规定一致的获取顺序，防止 enable、update、stop、remove 与查询刷新互相死锁。

多项目共享程序安装；项目配置、版本选择和事实索引隔离。共享 Provider 的兼容矩阵及并存能力必须先验证，不能假定多个不兼容版本可以共用同一数据库或守护进程。

### 稳定 MCP 入口

宿主连接稳定入口，入口按固定项目身份选择后端。入口在请求到达时重新检查项目状态，在明确的切换边界释放旧后端并连接新后端；首版不引入永久轮询。

已连接入口的任务应支持：尚未配置时返回状态；enable 完成后恢复查询；stop 后返回已停止；再次 enable 后恢复；update 后按验证结果切换后端。工具名称和协议保持稳定，不把跨版本会话缓存或 continuation 复用于新后端。

发现错误项目、配置歧义、配置被替换或迁移失败时停止提供事实，不能回退到邻近仓库。入口本身升级与业务后端升级分开处理，不能承诺旧入口自动具备未来版本能力。

### Codex 接入边界

Atlas 内部重新加载项目状态与 Codex 重新加载 MCP 注册是两件事。

- 已运行支持恢复的稳定入口：以同一 MCP 连接的端到端测试证明恢复能力。
- 已运行旧版入口：不能通过替换磁盘文件声称运行中的代码已升级；需要验证宿主重连方式。
- 原任务没有 Atlas 工具：验证 Codex 是否有受支持的原任务重连/加载入口；缺少证据时报告连接待加载。

保留原任务上下文是首要体验目标。首阶段先验证宿主能力，再确定能实现到哪一步；不改 Codex 私有状态、不强杀宿主、不默认修改全局 MCP 设置。不得把首次宿主接入未完成伪装成 enable 完整成功。

## 输出与兼容

正常输出仅显示操作结果、项目、版本、索引和连接状态。失败输出具体步骤和可执行的下一步。`--json` 提供版本化结构、稳定错误码和退出码；`--verbose` 提供诊断详情。自动化不解析展示文本。

机器路径留在诊断信息和本机配置中，不提交项目仓库。旧接口继续兼容，文档首页收敛到四命令，高级命令保留在诊断文档。

## 实施阶段与交付

1. **能力核实与设计冻结（已完成）**：核对现有实现与稳定 Release 差异；验证宿主原任务重连能力；确定入口与后端协议、项目状态、锁顺序、共享 Provider 兼容性及恢复区所有权规则。设计和实验结果见 `ATLAS_SIMPLE_LIFECYCLE_DESIGN.md`。
2. **四命令基础实现（进行中）**：增加入口和统一管理层，复用现有能力，实现幂等、项目隔离、失败恢复和结构化输出。项目生命周期状态、原子发布和独立操作锁已经实现并通过全套测试；下一切片实现 `atlas` 入口及 enable/stop。
3. **同一连接恢复**：实现稳定入口及后端重连，在同一 MCP 会话中验证停止、恢复和更新；明确旧版入口与首次注册的宿主限制。交付端到端恢复证据。
4. **跨平台发布验收**：通过六平台、安装升级与故障恢复测试，整理简明使用文档和迁移说明，构建可审阅的发布候选。正式发布按后续发布授权执行；部署只使用已发布稳定资产。

阶段存在依赖，不把第二阶段的命令包装成功当作第三阶段的旧任务恢复成功。

## 验收标准

- 干净项目 enable 后，仓库身份准确、doctor ready、索引 fresh、深检健康、目标命中和跨项目负例通过。
- 重复 enable 不重复安装或无故重建；停止、恢复和移除均幂等。
- stop 后查询不会重新启动项目；停止和更新交错时无混合 generation、死锁或失控进程。
- 同一 MCP 连接经历未配置、启用、停止、恢复、更新，结果状态准确，旧 continuation 被安全失效。
- 更新下载失败、校验失败、迁移失败和进程中断时，旧版本与数据保持可用；停止项目保持停止。
- remove 不触碰业务源码和无关配置，其他项目继续查询，恢复区收据可用于验证恢复流程。
- 两个任务同时执行生命周期操作与查询时按规则串行；不同项目互不串用事实或误停共享服务。
- Linux、macOS、Windows 的 x86_64/ARM64 覆盖路径别名、权限、进程退出和升级切换。
- 发布资产包含实际验收提交；不能把旧稳定版的同名版本号当成修复分支已经发布。
