# Codebase Atlas Codex 使用体验与功能流程优化总计划

日期：2026-10-09；更新：2026-10-11。版本：第四版。状态：阶段零设计、基线与有限可行性出口独立复核通过；阶段一开发与兼容复核通过；阶段二未通过，本轮已按冻结失败门结束（7/10次实际启动：4次历史计量无效、3次有效采集，Python MCP资格缺失）；阶段三至四未开始，总计划未完成。

本计划先改善 Codex 使用现有 Atlas 能力的体验，再优化从定位文件到验证修复的工作流程。核心目标是让用户照常描述问题，Codex 能以较少等待和阅读取得可核对的代码证据；Atlas 不可用或定位失准时，任务仍能安全继续。

2026-10-11 用户要求建立长期计划，按计划执行，不反复停下来询问；每完成一个阶段，由独立 agent 复核，通过后继续。此指令更新此前仅阶段零的执行授权：本计划范围内的本地开发、相关测试、独立开发工作区与分支、私有实验连接、必要的真实开发与评分会话可在具体方案及权限经独立复核后执行，不逐项重新请求用户批准。真实会话优先通过已核验 CLI 启动，不自动创建或消息发送到其他用户侧栏聊天。产品安装和用户项目部署、全局配置修改、commit/push/PR/合并/发布、破坏性清理、新语言或 Rust 工作仍不包含在本次范围内。

2026-10-10 取消的工时上限继续取消。独立复核不替代实证，不扩大用户授权，不修改冻结的正式验收门槛。旧文档中的等待阶段实施批准与旧会话额度作为历史记录；当前执行以本版第十二节为准。阶段零实际失败和缺口见 [最新执行结果](CODEX_EXPERIENCE_STAGE0_EXECUTION_RESULT.md)，不得将连续推进授权写成阶段通过。旧 Rust 自动跟进保持暂停。

## 一 产品目标和责任分工

Atlas 负责提供有限候选文件、精确符号身份、关系与测试证据，以及索引代际和完整性状态。Codex 负责阅读源码、判断候选是否相关、形成和验证假设，并在用户授权范围内修改代码与运行测试。用户不需要学习工具名、查询参数或索引管理命令。

成功不是增加工具调用次数，而是在修复正确性不下降的前提下，让真实任务少走弯路。Atlas 返回候选不等于已经找到根因；符号存在也不等于与用户问题相关。

## 二 现有基础和历史边界

现有产品文档列出了 Python 和 TypeScript/JavaScript 支持、最多两个启发式候选文件的 `locate_files`、要求精确符号的 `analyze_change`、紧凑结果以及索引刷新与恢复能力。实施前必须重新确认准确候选版本、接口、安装来源和目标项目身份，不使用历史版本或旧会话作为当前事实。

历史 M33 和 M34 表明，直接从自然语言断定具体函数的路线未通过独立质量门。M37 的文件定位独立验收在 16 个任务中有 13 个把正确实现文件排入前两位；该成绩不等于真实修复成功率，也不证明本轮候选会更好。历史任务可用于回归，但不得作为新的独立验收任务。

## 三 范围和非目标

本轮只优化现有支持语言上的使用指引、工具描述、结果呈现、错误与降级体验、调用编排及验收。优先复用现有接口和紧凑输出，不提前增加新接口。

不包含 Rust 启用、重型语义索引、自动确定根因、新语言、全局 MCP/editor 修改、云同步、新 UI 或后台常驻服务。索引管理能力不能因为“少打扰”的目标而越过授权：停用项目不自动启用，外部部署、配置修改和首次索引仍按 canonical deployment 规则处理。

空间清理是独立工作，不在本计划中删除资料。复用已验证环境和数据，避免复制全套上游仓库；验收所需的源码、锁文件、报告、原始结果和恢复材料须保留。新试验材料限定为私有临时环境，机器路径不提交。

## 四 阶段零 基线与验收契约

在任何实现前确定准确 Git SHA、工作分支、已安装版本、Provider 身份和测试环境，保留用户未提交修改。只读核对上游 stable/main 与所需体验能力，确定独立开发基线及必要的移植范围；不得直接从当前 Rust head 分支而默认携带全部 Rust 历史。当前 Rust checkout、PR #21 和未跟踪文档保持原样。分支、工作区创建和必要文档复制在第四版范围内经方案复核后执行；不 checkout/reset 清理现有内容，不写 main，不强推。

检查现有入口、工具描述、项目指引、结果契约和相关测试。Atlas 可用时先确认 `project_status` 的根目录与当前 Git 根一致，再对准确符号做有界分析；不可用时只读源码检查，不创建替代导航索引。记录缺失的运行证据。

基线覆盖六类情形：

1. 已知文件的局部修改，应直接阅读。
2. 不知道实现位置，适合候选文件定位。
3. 已知符号的跨文件修改，适合关系与测试分析。
4. 候选不相关、零结果、同名歧义和部分结果。
5. 工具不可用、停用、繁忙、启动超时和身份不匹配。
6. 索引过期、授权刷新失败、旧代恢复和长会话源文件变更。

明确三组数据：开发回归集、真实宿主开发验证集、封存端到端独立集。前两组可用于开发，不得与第三组复用任务、真值或已观察定位结果。第二阶段只用真实宿主开发验证集；第四阶段才解封独立集。独立评分者保管真值与隐藏测试，工作 agent 不查看；真值有效性须预先独立验证。历史任务排除清单递归覆盖先前调参与验收观察。

阶段零冻结基线 SHA、安装与 Provider 身份、干预范围、评测脚本、主指标和资源契约，不冻结尚未实现的候选。每次开发验证记录当次候选身份；第四阶段前再冻结最终候选源码与文件哈希、构建/环境 receipts、工具描述和使用指引。候选改变后原开发结果不能代替新身份的验证。

独立集期望包含 12 个任务、Python 与 TS/JS 各一个真实仓库，覆盖定位、跨文件修复和失败回退，另设安全控制。12 个配对任务至少需 24 个真实会话。阶段零以已有记录估算监督、评分和恢复成本；必要的少量开发会话校准按第十二节的会话账本与方案复核执行；尚未运行则成本记为未知。首次正式运行前冻结任务数、单会话评测超时、串行或隔离并发规则和资源条件。评测超时用于配对公平性和失败计分，不是产品开发的工时上限；须由校准证据确定，不削减必要安全控制或独立性。

记录端到端耗时、首个有效证据时间、冷启动与热查询时间、查询和搜索次数、重复阅读、输出量、用户询问及异常回退。实际 token 用量不可观测时标为未测，不以字节数或工具调用数代替。最小可复核记录包括宿主事件戳、工具名与状态、源码区域位置、候选身份、会话边界及评分理由；提示词或源码正文的额外采集须单独确认范围。不为最小化而删除评分所必需的证据。

在阶段零预注册唯一效率主指标，不在结果出来后从多个指标挑选。首个有效证据定义为首次读取到隐藏真值对应的实现区域且满足预先冻结的任务判定条件；独立评分者对去方案标识的轨迹评分，以真实宿主事件戳计时，不凭最终回答反推。重复阅读的区域与去重规则、零基线、冷/热状态、超时与未完成任务如何计分均须预注册。无法可靠采集主指标则停止收益验收，不临时替换指标。按冻结超时上限计入未完成会话的耗时，并报告完成率，不能只对成功任务计时。

只读确认真实宿主是否支持项目范围内的对照隔离：两组共同的非 Atlas 开发规则保持一致；对照不加载 Atlas 工具及仅 Atlas 特有路由，候选加载准确版本工具与对应指引。保存配置差异、实际工具发现和恢复方案，不改全局配置。未发布候选只能通过经独立复核的私有临时试验连接进入宿主，不冒充 stable Release 用户部署，不改现有用户项目。宿主接入、对照隔离或轨迹采集不可实现时，记为路线未完成，不以 stdio 脚本替代。

出口：准确基线、三组任务分离、宿主接入可行性、对照隔离、独立评分安排、主指标、任务级正确性门、真实会话成本与资源限额、平台范围和恢复对象全部明确。独立集的真值封存由评分者负责，开发者只见契约与清单摘要。本机宿主结果不代表其他平台；阶段零列明兼容回归需覆盖的平台，未测项不得计通过。恢复对象限于候选源码/指引、私有连接、授权临时配置与进程，不覆盖其他项目共享安装。设计出口未闭合只报告缺口；通过独立阶段复核后，按第十二节自动进入阶段一实现。

## 五 第一阶段 使用体验优化

先改善现有能力的使用方式，不调整检索排名或图算法。

- 明确何时跳过 Atlas，避免简单任务多一道查询。
- 自然语言先走有限候选定位；确认具体符号后再使用 `analyze_change`。
- 优先使用既有 compact 模式；候选呈现文件、可核对位置、推荐依据和下一步，不伪造概率或置信度。
- 保留完整性、代际、来源和警告信息，不为简短而隐藏 `partial`、`not_run`、`error` 或截断。
- 错误说明只给原因、当前影响和安全下一步，避免重复提示。
- 对 busy/startup 类暂时错误设置有限等待；等待耗尽则降级，不无限重试。
- 少询问普通读取步骤，但不扩大修改、执行、刷新或部署权限。

优先修改版本化、项目范围内的使用指引、工具说明和结果呈现。若需要新包装接口，先证明现有接口无法满足目标，并单独补充设计与兼容性审查；不得把多个不同权限的动作隐式合并。

开发回归必须覆盖全部六类场景，保持既有 JSON/MCP 契约和默认行为兼容。文案与包装层不应重复实现 Provider 的身份、完整性或刷新规则。

出口：场景回归全部通过；身份错配、越权、错误结果被呈现为事实的事件均为零；局部任务不增加不必要的 Atlas 调用；紧凑输出不丢失关键证据。尚未通过真实宿主验证时只称为开发完成。

## 六 第二阶段 真实 Codex 体验验收

用新鲜 Codex 任务验证实际工具发现、使用指引触发、查询调用与降级。CLI/stdio 测试通过不能替代此阶段，不能用脚本模拟轨迹冒充真实宿主体验。

必要的真实 CLI 实验会话、私有临时连接和私有项目 MCP 配置按第十二节复核后执行。不得改现有用户项目或全局配置；CLI 普通测试不能代替真实宿主会话，宿主验收未完成时不得宣布体验优化完成。

验收要求用户仅用普通问题描述，不指定 Atlas 工具。检查：已定位的小任务是否跳过工具、未知位置是否安全获得候选、关系查询是否使用准确符号与路径、不可用时是否继续常规阅读，以及是否发生重复调用与多余询问。

出口：宿主开发场景通过，且调用轨迹证明按需使用而不是强制增加调用。第一阶段只允许一次基于明确失败原因的修订；修订使用新的宿主开发任务，第四阶段独立集始终不解封。缺失真实宿主证据时不宣布通过或进入第三阶段；复核通过后继续。

## 七 第三阶段 功能流程优化

第二阶段通过后，完善“问题描述、候选文件、源码确认、精确关系、修复与测试”的闭环。此处的修复和测试由 Codex 在原任务授权下执行，不由 Atlas 擅自执行。

每次定位最多接受现有接口允许的两个候选。阅读后区分相关、不相关和证据不足；不得将未检查候选标为相关。连续两个候选均不相关，或耗尽冻结的调用与等待预算，转普通搜索，不换同义词反复请求同一批文件。

确认符号身份后再查关系和测试；同名歧义先澄清路径或 owner，不选择方便的结果。缓存或复用证据必须核对仓库、源码状态和索引代际；源码变更后不能沿用旧位置与结论。缺失测试关系不等于不存在相关测试。

减少相同证据的重复查询与阅读，不添加持久化的平行索引。最终回答说明定位依据、修改范围、实际测试结果和仍缺失的验证；相关文件不等于必须修改的文件，相关测试不等于充分测试。

如果流程分析证明检索质量才是主要瓶颈，结束本轮编排工作并提交新的检索实验提案，不在本计划中恢复旧语义路线或无限扩大候选数量。

出口：闭环及所有异常分支有回归证据，不能确认根因时能够安全退出。第三阶段同样最多一次有明确新假设的修订。

## 八 第四阶段 独立端到端验收与收尾

正式验收前冻结最终候选和两种真实宿主配置，再解封独立集。对普通 Codex 与 Codex 加 Atlas 做配对比较，按阶段零定义隔离工具和 Atlas 特有指引。使用没有开发/审查历史的独立会话、相同源码快照、模型设置、权限、测试环境与公共任务描述；工作会话不得看到隐藏真值、评分者上下文或另一方案轨迹。不同方案任务顺序均衡，隔离修改与缓存，串行时计入不同冷/热条件。正式集仅运行一次，不调参、改门或重跑；候选身份在正式运行中改变则验收无效。失败、超时和未完成任务不得从统计中删除。

建议验收门槛如下，阶段零可在首次运行前调整并冻结，运行后不得降低：

- 逐任务按独立隐藏测试与任务判定条件评分，报告配对的双方通过、仅对照通过、仅候选通过、双方失败四类结果。仅对照通过而候选失败的任务必须为零，不能用其他新增成功抵消；安全控制全部通过。两方案全部失败或收益主指标不可测时不得宣布成功。
- 不得出现新增越权、跨项目事实、虚构根因、隐藏不完整结果或未运行测试被报为通过的事件。
- 对预先指定适合 Atlas 的任务，唯一预注册效率主指标的配对改善中位数至少 20%；其他指标只作辅助，不能替代主指标。全部任务的完成耗时中位数不得恶化超过 10%，计入超时与失败。主指标的配对改善公式及零分母处理在阶段零冻结。这些是提议门槛，不是产品性能承诺。
- 已知文件任务不增加无必要的图查询；无权限边界的普通读取不增加多余授权询问。
- 全部失败任务保留独立分类和轨迹摘要；小样本结果只用于本轮范围内决策，不宣称普遍统计优势。

输出分为三种结论：接受候选、保留经自身验收的体验改进但拒绝流程候选、未证明收益并恢复稳定行为。未通过完整冻结门槛不得宣称收益成立。缺真实宿主、契约要求的平台或结果时记为未完成，不用其他测试替代。正式验收失败后结束本轮，新的实验需要新任务集和重新批准，不沿用旧独立集或阶段修订额度。最终发布或安装升级是后续单独批准事项。

## 九 质量推进与停止条件
