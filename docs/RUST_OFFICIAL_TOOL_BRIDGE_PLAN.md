# Rust 官方工具安全接入：有界可行性计划

日期：2026-10-07。状态：独立审查及修订复核通过，待用户确认 B0 研究；本轮未启动实验。
本文件细化 [执行隔离计划](RUST_EXECUTION_ISOLATION_PLAN.md) 的 I0，
属于 [正式启用计划](RUST_PUBLIC_ENABLEMENT_PLAN.md) 第二阶段，不替代原出口。
目标是回答“现有约束下是否存在可验证的接入路线”，不预先承诺路线可行。
Rust 验收 heartbeat 已按用户要求暂停，本计划不恢复自动检查。
独立审查记录见 [专项审查报告](RUST_OFFICIAL_TOOL_BRIDGE_PLAN_REVIEW.md)。

## 1. 为什么暂停推进

基线源码：`26b7ea1622e1033854d938109c14c78830844618`。
最近已核验 CI `37476074007` 和五平台内部安全 `37476073919` 均通过，
包括原生 Windows ARM64。它们不代表 I0、第二阶段或产品验收通过。

当前 `scripts/rust_cooperative_broker_protocol.py` 的 `Session` 只接受
`own-fixture-observe-v1`；`scripts/rust_broker_command_feasibility.py` 明确是
自有 Python 命令收集前置实验，不是受限请求方与官方工具的原生接入桥。
Windows deny-all 实验证明有限调用路径被拒绝，也会禁止合法 Cargo/rustc 子进程。
直接去掉 deny-all 不能沿用其限制证据；再增加自有请求方测试也不证明官方兼容。

已保存的固定官方源码证据：Rust 1.98.0 commit
`88d9e12ae178fab0fb5cc050a94da85685d449ea` 下的 rust-analyzer
`cargo_workspace.rs`、`toolchain_info/rustc_cfg.rs`，以及 Cargo commit
`797e8a9bca276c1c9f9f738d2a20f484fa4eea9d` 的 `target_info.rs`。
它们构造原生 Cargo/rustc 调用，不是现有自有协议的客户端。
接入桥尚不存在，不代表所有候选机制都不可能。

保留原失败：源码 `514d813673c5ae537d5edb299b51c2033cad5258`、scanner run
`37424646449`、Windows ARM64 job `112141434618`，热会话配置变化触发禁止
wrapper 标记。返回 stale 或随后杀进程不是修复；后台重载仅是待验证解释。

## 2. 不变边界

- 五平台、T0/T1/T2 语义、既有时间及内存门不变；稳定 0.27.0 Rust 保持关闭。
- 锁定官方工具原字节、逐文件来源/许可证校验，不补丁、不重新签名，不冒充身份。
- 普通账户，不装驱动、不提权、不创建新的系统 profile、不改全局防火墙/ACL。
- 不部署现有项目、不改全局 MCP/editor、不创建真实新 Codex 任务或临时连接。
- 只写获批候选分支及 Draft PR21；不写 main/tag/Release/PyPI/上游。
- 不把物理 parent 换成逻辑 parent；精确 executable/argv/cwd/env/parent/stdin、
  loader/解释器、网络和后代约束仍按 I1 合同检查。
- 只有明确的执行前强制边界才算防护。PATH 包装、事后 matcher、日志观察、
  杀进程、没有 marker、单独 offline 环境变量均不足以通过。

## 3. B0：只读路线筛选，先找到桥

先复用既有固定源码和原始证据；新增原生 API 结论须读取适用的官方文档，
记录版本、平台、具体 API 和权限条件。不执行官方工具，不改配置或权限。
Atlas 不可用时只用有界源码检查，不创建替代索引。

至多审查三条不同机制路线，最多两轮“检查—独立质疑—补证”；每轮至多
90 分钟主动研究，外部等待单列，不以等待延长主动预算。预算到达或两轮均
无新机制证据即提交结果，不重复跑绿色 CI或同类 fixture 来延长研究。
“尚未找到”不写成“理论上不可能”。候选不足三条也可提前结束。

每条路线必须回答：

1. 官方 RA→Cargo→rustc 的哪个原生启动边界被接入？未经修改的程序为什么
   会走此路径？必须给固定源码/API依据，不假定它会主动发送自有 broker 协议。
2. 哪个可信组件在 exec 之前绑定并强制命令、环境、工作目录、必要 stdin？
   请求批准后可变参数/路径/文件/管道如何不能被替换？不能仅检查后放行。
3. 谁实际创建后代？物理 parent、工具身份与既有合同能否同时保持？
4. 非合作启动、可信工具被恶意参数利用、解释器/loader、后台重载与控制器死亡
   如何受同一边界约束？broker 本身不能成为任意执行代理。
5. 完整进程树的网络/IPC如何限制？逐项标识 IPv4/IPv6、TCP/UDP、DNS、Unix
   socket、继承 fd/handle、io_uring；只支持子集必须写明，不称完全禁网。
6. 五平台各自是否有公开支持机制、原生 ARM64、官方签名兼容和无新权限路径？
   缺平台证据记未知/blocked，不用一平台替代。此轮不要求运行五平台实验。

产出每条路线的机制/合同条目/来源/已证实/未知/冲突矩阵，及一个推荐或
“无可推荐路线”。表中的“可考虑实验”只代表研究入口，不是平台资格。
若仅靠修改工具身份、parent 合同、权限、平台/能力承诺才可行，单独列出
选项和代价，请用户决定；本计划不授权这些改变。

## 4. B1：独立决定是否值得实验

独立 agent 检查 B0 原始来源和矩阵，优先挑战官方调用路径、TOCTOU、物理
parent、非合作绕过、签名及网络盲区。未解决 P1 时不标记可实验。
只有至少一条机制满足当前边界、且无明显五平台硬冲突，才提出实验卡：
精确平台/工具身份、执行边界、允许命令、正负控制、观察器、预算和清理方法。
未知平台可保留未知，但不能宣称五平台可行；已知硬冲突先提交路线选择。

本次用户同意仅覆盖计划制定和独立审查；B0 研究与后续 B2 实验执行在交接时
明确请求确认，不能从此计划自动推断获准实验、I1 冻结或生产接线。

## 5. B2：获准后，一个平台的最小官方工具实验

由 B1 证据选择平台，先记录选择理由和其余平台风险，不挑选结果后换平台。
执行确认前，实验卡须冻结 B2 总主动工时、单轮及总体次数/时间上限，包含机制
实现、观察器准备、完整正负例和两次以内修订。达到上限即保存证据交接，不借
平台切换、修订或准备工作无限延期；必要安全清理仍必须完成，单列其实际耗时，
不得因研究预算耗尽遗留所属进程，也不能把超出 cleanup 宽限写成通过。
只复用逐文件验证的官方工具；缺工具则列出独立准备授权，不隐式联网或安装。
使用自有临时最小跨文件 Cargo workspace，预先冻结定义/引用真值、工具及
source/config身份。普通分析路径使用未经修改的官方 RA/Cargo/rustc，
不是用自有请求方模拟兼容。临时 harness 不宣称 installed-wheel 验收。

实验卡必须在执行前冻结以下门；未写明观测和强制方法不得启动：

- 同一限制域的正常初始化、至少一项跨文件 definition 和 references 有正确来源。
- wrapper 初始/热会话变更、未知 argv/env/cwd/stdin、response file、项目输入
  编译、shell/解释器/插件/下载及直接非合作启动：在 exec 前明确拒绝。
- 批准后参数/文件/输入替换用确定性 barrier 验证；保持真实物理 parent 合同。
- 网络/必要 IPC 的执行前限制及实际正负观察，按合同逐项覆盖；不支持记 blocked。
- 同限制域、同 scratch 权限的正向控制证明观察器能看见实际执行/连接，
  区分 attempt、deny、actual execution、marker，拒绝只看标记缺失。
- 控制器断开/死亡、超时、启动失败、输出溢出及 cleanup 失败无 unsandboxed
  fallback；记录 owned tree 退出，不能在清理结束前宣称成功。
- 三次独立新鲜进程，完整树和身份/命令/拒绝/结果/退出证据；缺观察或 skipped
  记未完成。版本探测/启动/readiness/query 使用已冻结共享剩余 deadline，
  cleanup 沿用 10 秒宽限，不提高预算或资源门来消除失败。

最小实验失败即保留原始证据并停止晋级。至多两次有明确新假设的机制修订，
每次修订须复核实验卡，重跑完整同一正负集；若需要边界变化立即停下请求决定。
一次平台成功仅算该平台 I0 证据，不标记第二阶段完成，不修饰原 Windows 失败。

## 6. B3：回到原计划，不跳门

单平台实验及独立原始证据审查通过后，才提出五平台 I0 扩展。
五平台可行性全通过并独立批准 I1 合同，才进入 I2 生产接线和 I3 原生负例。
保留原 Windows ARM64 wrapper 用例，在新精确源码上重新运行并核查完整证据。
完成第二阶段准备并发、失败回滚及全部安全出口后，才进入第三阶段
installed-wheel/fresh stdio、生命周期、冻结语义和资源门；随后两个外仓和
真实新 Codex 授权、第五阶段独立验收、单独公开启用授权均不变。

## 7. 交接与停止条件

原始证据和机器路径只放忽略的评估目录；可发布文档只保存身份与摘要。
每次记录 exact source/tool identity、研究阶段、来源、进程/平台、已证明与缺口。
当前 CI 身份只作历史基线；若后续代码变化，旧 SHA 证据不得继承为新资格。
不为计划审查重触发 workflow，不恢复 heartbeat，无成果时不重复通知。

向用户只提交以下之一：

- 有具体桥和未变边界：附独立审查的研究结论、最小实验卡，请求执行确认。
- 只有边界变更才可推进：列明确选项、风险和所需授权，等待决定。
- 有界研究未找到路线：列已排除机制、尚未知项和继续研究价值；停止扩展工作，
  不把预算耗尽当作技术不可能，不宣布 Rust 可用。

计划通过只表示研究/实验顺序合理，不是实现、安全资格或公开启用通过。
