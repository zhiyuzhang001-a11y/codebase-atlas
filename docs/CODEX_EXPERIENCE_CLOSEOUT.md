# Codex 使用体验与功能流程优化收尾

日期：2026-10-11。最终决定：用户认为预期收益不足以抵消实施困难，暂停项目开发并归档成功、失败及经验。**总计划未完成，阶段二未通过，阶段三和四未开始；没有证明效率提升。** 此次收尾只发布文档与候选补丁附件，不合并产品改动，不发布版本，不恢复实验或自动跟进。

## 原目标与最终范围

目标是在不改变检索排名和图算法的前提下，让 Codex 按需使用 Atlas：已知局部任务直接读源码，未知位置先有限定位，确认身份后做精确关系分析，保留 partial、来源和截断信息，工具不可用或索引过期时安全回退，最后用独立配对任务验证正确性及效率。

计划依次包含阶段零的基线、隔离与测量准备，阶段一的体验改动，阶段二的真实宿主验收，阶段三的完整修复流程，阶段四的独立配对评测。阶段之间必须独立复核通过，不能把实现或测试通过写成正式收益。

实际结果是阶段零的设计、准确基线及**有限可行性出口**通过；阶段一**开发复核**通过；阶段二本轮终止且未通过；阶段三、四未进入。用户随后明确要求暂停开发，再授权本次 GitHub 收尾。收尾不是恢复开发，也不将此前的终止或暂停改成完成。

## 失败与未完成事项

阶段零原控制的全局指引隔离失败永久保留。只设置 `--ignore-user-config`、清空 MCP 或禁用技能不能证明全局 AGENTS 没有加载。后续采用的是独立审查的有限控制合同，不是追认原隔离成功。tools-only 服务的资源枚举返回 `-32601 Method not found`，原“必须返回空列表”的能力门不成立；不能把错误等同于空结果。

四场公开校准工作中，旧 A-control 因启动器采集缺失永久无效，用量和计量未知。其余三场可用于有限采集检查，但只有 B 有有效配对；不具备正式效率比较条件。评分有两次启动尝试、一个实际模型会话，首次 Git trust 失败发生在模型会话之前。这些计数不能混为成功会话总数。

阶段二累计 **7 次实际启动，上限 10**；前四次计量无效，后三次采集有效。剩余额度不能覆盖失败停止门。

- 第三场 TS 资格探针：原生日志有九个唯一完成事件、没有启动事件，旧控制器错误要求启动/完成集合相等；两项 unresolved。

## 可复用的经验

1. **测量工程可能成为主要成本。** 本次多次停在宿主隔离、事件契约、收尾和运行条件，而非产品算法。小型体验改动是否值得完整独立实验，应先用有限校准确认成本和可观测性；准备工作不能冒充收益。
2. **基础设施资格与自然任务行为分开验收。** 一个合理任务可以完全不调用 Atlas。资格任务若依赖模型自然调用，可能得到正确答案却没有所需技术证据；反过来强制调用也不能证明按需体验良好。
3. **正确性、采集有效性、安全、收益是四个独立判断。** 测试通过但采集无效仍无资格；采集有效而证据不足也不能通过阶段；工具被跳过可以是合理行为。
4. **先确认实际加载，再解释退出码。** Node 在严格权限下读取 OpenSSL 配置失败时，rc1 并不意味着业务断言已执行。进程内参数修正和明确测试计数比扩大权限更合适。
5. **采集器依据真实协议建立闭环。** 无匹配是已完成的业务结果；缺少启动事件不必然意味着完成事件不完整；合法文件 patch 的路径表示也应准确覆盖。必须保持严格映射、身份和预算，不能宽泛吞掉未知事件。
6. **紧凑输出必须保留证据边界。** provenance、resolution、partial、not_run 和截断关系到结论可信度，不能为了短输出删除。
7. **未知来源保持未知。** 外部配置漂移和完成后 SIGTERM 没有归因证据。用户表示未主动修改，仍不足以确认来源；不覆盖用户配置，也不推断信号发送者。
8. **预注册停止条件必须兑现。** 失败后重试、换任务或增加额度容易把有限开发验证变成持续寻找通过。用户最终判断收益不值得继续，是成本决策，不是技术不可能的证明。

## 成本与适用范围

本机实证范围是 macOS 27 arm64、Codex CLI 0.162.0-alpha.17.2；其他 native hosts 和平台未验证。校准安装为 Atlas 0.26.1，候选源码为 0.27.1，Provider 为 0.10.8-atlas.2+e088a41b；这些角色保持分开。

阶段零计数为 9 项实际探针、4 场工作、2 次评分启动尝试及 1 个实际评分会话。已发出的官方 usage 和 observer 时长保存在[校准成本摘要](experience-closeout/calibration-costs.json)。A-control 用量、完整人工准备/监督/恢复工时、美元费用和全项目实际成本未知；不从目标 token 总数、工具调用数或短小样例推算。Provider 和预建索引属于准备热状态，缓存状态未知，不声称冷启动或效率优势。
